Memória de IA auto-hospedada numa VPSSelf-hosted AI memory on a VPS

Mantenho uma memória longa compartilhada entre meus agentes de IA (Claude Code e Codex) com o projeto de código aberto ai-memory. O serviço rodava local no Windows até o Smart App Control bloquear o binário sem assinatura. Migrei para uma VPS Linux acessível só pela rede privada Tailscale, sem nenhuma porta pública: firewall que nega tudo por padrão, SSH e o serviço escutando apenas na interface da tailnet, fail2ban, atualizações de segurança automáticas e acesso somente por chave. O serviço roda sob systemd como usuário sem privilégio e em sandbox, sem novos privilégios, com o sistema de arquivos protegido e o conjunto de capacidades vazio. Exige um token em todas as rotas, menos o healthcheck, e valida os hosts permitidos contra DNS rebinding. Opera em leitura com escrita manual via MCP e envia um resumo diário por um timer. A superfície de ataque pública ficou em zero. I keep a shared long-term memory across my AI agents (Claude Code and Codex) using the open source ai-memory project. It ran locally on Windows until Smart App Control blocked the unsigned binary. I moved it to a Linux VPS reachable only over the private Tailscale network, with no public port: a default-deny firewall, SSH and the service listening on the tailnet interface alone, fail2ban, automatic security updates and key-only access. The service runs under systemd as an unprivileged user and sandboxed, with no new privileges, the filesystem protected and an empty capability set. It requires a token on every route except the health check and validates the allowed hosts against DNS rebinding.
